What dropping React Native bought you

  • No 3 MB WASM download. Skia was needed to draw on native; the browser already has Canvas 2D, which is faster to start and simpler to debug.
  • Text stops being the hardest problem. On React Native the caret drifted from the rendered glyphs. In a browser, text editing is a contenteditable div positioned over the canvas — the browser handles the caret, selection, IME and Arabic shaping natively.
  • Clipboard paste and desktop file-drop are first-class instead of platform-split workarounds.
  • Real CSS cursors for the hover states you asked for, instead of a touch-target fallback.

The app still works on a phone or tablet browser — it's responsive and touch-aware — it just isn't installed from a store.

Architecture

One deploy, four bindings

A single Cloudflare Worker serves the app, the API and the sync server, with the database, object storage and board rooms bound directly to it. No CORS, no second vendor to authenticate against, one wrangler deploy.

Browser
  │  static assets (free, unmetered)
  │  REST calls        ──►  Worker  ──►  D1        folders, boards, sharing
  │  image reads       ──►  Worker  ──►  R2        cached at the edge
  └─ WebSocket         ──►  Worker  ──►  Durable Object "board:abc123"
                                          ├─ Yjs document in memory
                                          ├─ SQLite: update log + snapshots
                                          └─ every open socket for this board

Firebase Auth ──► ID token ──► verified inside the Worker on every request

Model

What a board is, and why undo stays yours

Y.Doc (one per board, lives in its Durable Object)
├─ meta      title, background, grid settings
├─ elements  Y.Map<id, Y.Map>   ← field-level merge, not whole-object overwrite
│    ├─ id, type, x, y, w, h, rotation, opacity
│    ├─ z          fractional index — "a0V" sorts between "a0" and "a1"
│    ├─ locked, hidden, parentId (frame or group)
│    └─ style      fill, stroke, dash, radius, shadow, font…
└─ awareness (never saved)
     cursor · selection · viewport · laser trail · "is typing"

Each element is its own Y.Map, so if you change a shape's colour while someone else drags it, both changes survive. Z-order uses fractional indexing, so reordering rewrites one row instead of renumbering the board.

Every local change is tagged with an origin unique to your tab, and the undo manager is scoped to that origin — so CtrlZ walks back through your edits only.

Decide this in Phase 4

You move a shape. A colleague moves it again. You press undo. Should it snap back to your old position, discarding their move (the default), or should it refuse and tell you the shape has changed? One line of policy, very different feel. I'll build the default and leave the switch exposed.

A share link carries a role and an audience — anyone with the link · signed-in users only · anyone at a domain · named people only — and grants attach to a folder or a single board, with board-level grants overriding what they inherit. Your case (public read, two named editors) is one link at viewer plus two rows at editor.

Enforced in the Durable Object, not the UI

A viewer's WebSocket is accepted in read-only mode: they receive edits and broadcast a cursor, but the room rejects any document update they send. Hiding the toolbar is cosmetic — the room is the actual gate.

Working agreement

How you'll check each phase

You say "do phase 3", I build it, and you get something to open. How you open it depends on the phase:

  • Phases 0–4 need nothing from you. They're pure browser code, so I'll bundle each into a single self-contained page and publish it as an artifact you can open on any device and click through against the checklist.
  • Phases 5 onwards touch the backend, so they need your Cloudflare and Firebase accounts. You'll get a real URL on your own Cloudflare deploy. See what you set up — about twenty minutes, once, before Phase 5.

Every phase below ends with a numbered checklist. Each item is a thing you do and a thing you should see. If any item fails, that phase isn't done — tell me the number and I'll fix it before we move on.

Each phase also ends with a gate: the one thing that, if it doesn't hold, means we shouldn't build on top of it yet.

The build

Nineteen phases

  1. Teardown and skeleton

    small

    Delete the calculator. Stand up Vite + React + TypeScript, ESLint and Prettier, Vitest and Playwright, the folder layout above, a wrangler.toml, and GitHub Actions running lint, typecheck and tests on every push.

    How you check it

    1. Open the repo on the branch — no calculator files remain, and the README describes a whiteboard.
    2. The GitHub Actions run on the latest commit is green.
    3. Open the preview I send — you get an app shell with a header and an empty canvas area, no errors in the browser console.
    4. The page is readable in both light and dark mode (flip your system theme).

    Gate — CI green and the shell loads clean. Everything else builds on this.

  2. The infinite canvas

    large

    The viewport and renderer — the foundation everything else sits on. Layered canvases (static content, the thing you're currently dragging, and the overlay), retina-correct rendering, off-screen culling, the dot grid, and every way of navigating: wheel, trackpad, pinch, Space-drag, zoom to fit, zoom to selection, 100%, and the minimap.

    How you check it

    1. Scroll to pan. Hold ⌘/Ctrl and scroll to zoom — it zooms toward your cursor, not the centre.
    2. Hold Space and drag — the cursor becomes a grabbing hand and the board moves.
    3. Zoom right in — the dot grid stays crisp, never blurry (that's the retina handling).
    4. Click "5,000 test shapes" in the dev menu, then pan around. It should stay visibly smooth; the FPS readout should hold near 60.
    5. Press ⇧1 — everything fits on screen. ⇧0 — back to 100%, and the readout says 100%.
    6. The minimap in the corner shows a rectangle that tracks where you are; click elsewhere on it to jump.
    7. Open it on your phone's browser — two-finger pan and pinch-zoom work.

    Gate — item 4. If 5,000 shapes stutter, the renderer needs fixing before we add real elements to it.

  3. Shapes, selection and transform

    x-large

    The editing core: rectangle, ellipse, triangle, diamond, star and polygon; straight lines and arrows. Tools V H R O L A with a toolbar. Click, shift-click and marquee selection. Eight transform handles with rotation. Hover cursors. Snapping and smart guides, align and distribute. Group, lock, hide, reorder, duplicate, nudge. An inspector panel for fill, stroke, dash, opacity, corner radius and shadow.

    How you check it

    1. Press R, drag a rectangle. Press V, click it — eight handles and four rotation zones appear.
    2. Drag a corner — it resizes from the opposite corner. Hold Alt — it resizes from the centre.
    3. Hold ⇧ while drawing a rectangle — you get a perfect square. Same with ellipse → circle.
    4. Move the mouse slowly across a shape's edge and corners — the cursor changes shape at each one (↔, ↕, ⤡, ⤢, a rotate glyph just outside the corner, a move cursor over the body).
    5. Drag one shape near another — pink alignment guides snap to its edges and centre, and show equal-spacing marks when three line up. Hold ⌘ to ignore snapping.
    6. Drag a box around several shapes — all get selected with one shared bounding box. Drag it; they move together. Resize it; they scale together.
    7. ⇧-click one of them — it drops out of the selection.
    8. Alt-drag a shape — it leaves a copy behind. ⌘D duplicates with a small offset.
    9. Select a shape, press ⇧⌘L — it locks: clicking it does nothing, the cursor shows "not allowed", and the layers panel shows a padlock. Press again to unlock.
    10. Select two shapes, ⌘G — they group and move as one. ⇧⌘G ungroups.
    11. Overlap three shapes, use [ and ] — the stacking order changes one step at a time.
    12. With three overlapping items, use Send to back and Bring to front in the side panel to move one all the way with one click. Add a frame after the shapes and check that it starts behind them.
    13. Draw a wide rectangle inside a frame and use Fit width in the side panel or right-click menu. It should fill the frame from side to side and keep the same proportions. Undo should restore its earlier size and position.
    14. Select several, click distribute horizontally — the gaps become equal.
    15. Change fill, stroke width, dash and corner radius in the inspector — each updates live.
    16. Rotate a shape — it snaps to 15° steps and shows the angle while you drag.

    Gate — items 2, 4 and 5. Transform, cursors and snapping are the feel of the whole app; everything after this assumes they're right.

  4. Ink, text and images

    x-large

    Freehand drawing with pressure, both erasers, the laser pointer, full text with formatting, sticky notes, images from clipboard and desktop, connectors that follow shapes, and frames. Images are local-only in this phase — nothing is uploaded until Phase 6.

    How you check it

    1. Press P and scribble — the stroke is smooth and tapered, not a jagged polyline. With a stylus or trackpad pressure, it varies in width.
    2. Start a stroke, then hold ⇧ mid-stroke — it snaps live to a straight line from where you started. Release ⇧ and it goes back to freehand in the same stroke.
    3. Press E and scrub across a stroke — in object mode the whole stroke vanishes; in stroke mode it's cut where you scrubbed, leaving two pieces.
    4. Press K and move the mouse — a glowing trail follows and fades in about a second. Now hold the button and draw: the trail lingers ~5 seconds then dissolves. Reload the page — no trace of it is saved.
    5. Press T, click, type. Change font, size, weight, alignment, line height and colour — all apply live. Make a bulleted list.
    6. Type Arabic into a text box — it renders right-to-left with correct letter joining, and the caret moves the right way.
    7. Press N for a sticky note and type past its edge — the text shrinks to fit rather than overflowing.
    8. Copy an image anywhere on your computer and press ⌘V — it lands on the board at your cursor.
    9. Drag an image file from your desktop onto the board — it drops where you released it, at sensible size.
    10. Drag an image's corner — the aspect ratio is locked and it stays undistorted. Now hold ⇧ while dragging — it stretches freely. This is your rule, the reverse of Figma.
    11. Press A and drag from one shape to another — the arrow attaches. Move either shape; the arrow re-routes and stays attached.
    12. Press F and draw a frame around some shapes — moving the frame moves its contents with it.
    13. Press ? — the shortcut cheat sheet opens and matches what you just did.

    Gate — items 2, 4, 6 and 10. Those are the four behaviours you specified most precisely.

  5. Undo, saving and export

    large

    Everything moves onto the Yjs document — the model that will later sync. Per-user undo and redo, saving to the browser so nothing is lost on reload, crash recovery, copy and paste including between tabs, export to PNG, SVG and PDF, the ⌘K command palette, right-click menus and board templates.

    How you check it

    1. Draw several things, then press ⌘Z repeatedly — it walks back one action at a time, in the right order. ⇧⌘Z walks forward again.
    2. Undo a move, not just a create — the shape returns to its exact previous position.
    3. Draw something, then reload the page — everything is still there, at the same zoom and position.
    4. Draw something, then kill the tab mid-stroke and reopen — the board is intact.
    5. Open the same board in two tabs, copy a shape in one, paste in the other — it arrives with its styling.
    6. Go offline (airplane mode or DevTools), keep drawing — everything still works, and a "working offline" indicator appears.
    7. Export to PNG — the file has the right content, transparent background, and no toolbar in it. Export a selection only — you get just that.
    8. Export to SVG and open it in a browser — shapes and text are real vectors, not a bitmap.
    9. Press ⌘K, type "rect" — the command palette finds and runs the tool.
    10. Right-click a shape — a context menu with copy, duplicate, lock, delete and ordering.

    Gate — items 3 and 6. If saving or offline is unreliable, real-time sync will amplify it into lost work.

  6. Accounts, folders and boards

    large

    The first backend phase. Google sign-in through Firebase, verified inside the Worker; the D1 schema; nested folders; board create, rename, move, duplicate and delete; the dashboard with recents, starred and search; board thumbnails; and trash with 30-day restore. Needs your accounts set up first.

    How you check it

    1. Open your real URL. Click Sign in with Google — you land on a dashboard with your name and photo.
    2. Create a folder, create a folder inside it, create a board inside that — the breadcrumb reflects the nesting.
    3. Draw on the board, go back to the dashboard — the board's thumbnail shows what you drew.
    4. Sign in on your phone with the same account — the same folders and boards are there, and the board opens with your drawing.
    5. Rename a board, move it to another folder, duplicate it — all three stick after a reload.
    6. Search for part of a board's title — it's found. Star a board — it appears under Starred.
    7. Delete a board — it goes to Trash, not oblivion. Restore it; it returns to its original folder.
    8. Open a private browser window and paste your board's URL — you're asked to sign in, not shown the board.

    Gate — items 4 and 8. Cross-device sign-in and a locked door for strangers.

  7. Image storage on R2

    medium

    Images stop being local. Upload through the Worker to R2, automatic downsampling, blurred placeholders so shapes appear instantly, deduplication by content hash so pasting the same screenshot twice stores one copy, edge-cached delivery, and a per-board storage meter.

    How you check it

    1. Paste a large screenshot — a blurred placeholder appears immediately, then sharpens as it uploads, with a progress indicator.
    2. Reload the page — the image is still there. Open the board on your phone — it's there too.
    3. Paste the same image twice, then check your R2 dashboard — only one object was stored.
    4. Open DevTools → Network, reload the board twice — the second load serves images from cache, not from R2.
    5. Drop a 20 MB photo — it's downsampled before upload (check the stored size in R2), but still looks sharp when you zoom in.
    6. Board settings shows a storage used figure that matches roughly what you've added.
    7. Delete an image from the board, empty the trash — the R2 object is cleaned up.

    Gate — item 3. Deduplication is what keeps you inside 10 GB while pasting freely.

  8. Real-time collaboration

    x-large

    The Durable Object per board goes live: Yjs over WebSockets with hibernation, an auth handshake, live cursors with names and colours, selection halos in each person's colour, an avatar stack, follow mode, presenter spotlight, cursor chat, the laser pointer shared with everyone, connection status, reconnection with backoff, and version history built from the update log and snapshots.

    How you check it

    1. Open the same board in two browser windows side by side. Draw in one — it appears in the other within a blink.
    2. Move your mouse in one window — a labelled cursor moves in the other, in that person's colour.
    3. Select a shape in one — the other window shows it outlined in your colour with your name.
    4. Both windows drag the same shape at once — one wins cleanly, nothing duplicates, nothing freezes.
    5. Both type in the same text box at once — the characters interleave; nothing is lost.
    6. Press ⌘Z in window A after B made edits — only A's own change is undone. B's work is untouched. This is the one you specifically asked for.
    7. Turn off wifi in window A, keep drawing, turn it back on — a "reconnecting" indicator shows, then A's offline work merges in and both windows agree.
    8. Use the laser pointer in A — B sees the trail, and it fades on both.
    9. Click B's avatar in A — A's viewport follows B around as they pan. Click again to stop.
    10. Open version history, drag the scrubber — the board rewinds visually. Restore a point; both windows jump to it, and the recent work is still in history rather than destroyed.
    11. Name a checkpoint, make more changes, return to it — it's listed by name and restores correctly.
    12. Leave a board open and untouched for 10 minutes, then draw — it reconnects silently (that's hibernation working).

    Gate — items 4, 6 and 7. Concurrent edit, private undo, offline merge. This is the heart of the app.

  9. Sharing, permissions and comments

    large

    The share dialog with roles and the four audience settings, link expiry and revocation, folder-level grants with inheritance, guest viewers who pick a display name, the export toggle for viewers, comment threads with mentions and resolve, share notifications, ownership transfer, an audit log, and a public publish/embed link.

    How you check it

    1. Share a board as anyone with the link, viewer. Open it in a private window — you can see and pan it, and you're asked for a display name as a guest.
    2. In that guest window, try to draw — the tools are unavailable. Then open DevTools and try sending an edit over the socket anyway — the server rejects it. (I'll give you the one-line snippet; this is the test that matters.)
    3. Add a named person as editor while the link stays viewer — they can edit, the public link still can't.
    4. Switch the link to signed-in users only — the private window now demands sign-in.
    5. Share a whole folder as editor — every board inside opens editable, including one created afterwards.
    6. Override one board inside that folder to viewer — just that board is read-only for them.
    7. Set a link to expire, then move your clock forward (or set a one-minute expiry) — it stops working.
    8. Revoke a link while someone has the board open — they're dropped within seconds, not on next reload.
    9. As a commenter, leave a comment and @mention someone — they get notified; resolving hides the thread.
    10. Turn off "allow export for viewers" — the viewer's export menu disappears and the API refuses.
    11. Transfer ownership to another account — they can now manage sharing and you can't.
    12. Open the audit log — every share change you just made is listed with who and when.

    Gate — item 2. If the server can be talked into accepting a viewer's edit, nothing else here counts.

  10. Workshop tools and rich content

  15. Classroom: placeholders, the Answer role and owner locks

    large

    Placeholders with hint text that anyone can type into with one click, a new sharing role — Answer — that can type only in placeholders, enforced by the room, locks that guard against accidents but leave the owner free, and unlocking many items at once.

    How you check it

    1. Insert a placeholder with your hint text — one click or tap types into it, whatever tool is held; the hint goes, and comes back if the box is emptied.   16. Fixes: text boxes, the eraser, the side panel

    medium

    Your list of changes from after Phase 14, the quick ones first: text boxes that are only as tall as their text, an eraser that stays erased, a side panel that sits above everything and appears only when you want it, duplicates placed underneath, strikethrough, three more shortcuts, and boards shared for answering from the start.

    How you check it

    1. Click to add a text box and type a line — it keeps its width, and its height trims to the text, with no empty space below.
    2. In a one-line text box or placeholder, type a word and delete it — it stays one line.
    3. Erase part of a pen stroke, then draw again — the erased part stays gone.
    4. Nothing on the board — videos, link cards, frame numbers — ever covers the side panel.
    5. With the side panel switched on, select something or pick up the pen or highlighter — the panel appears, with no "Nothing selected" message; switched off, it never appears.
    6. Duplicate an item — the copy lands directly below it, lined up, not on top of it.

Risks

What could still go wrong

  • The free tier's real ceiling is 100,000 writes a day

    Shared between D1 and each board's SQLite. Batching saves to about one per second of active drawing gives ~27 hours of editing per day across everyone. Comfortable for you; a hard limit if this became a team product. Mitigation: adaptive batching that widens under load, and a usage meter so you see it coming.

  • Board history grows forever

    An append-only log is what gives you "undo anything from months ago", but a two-year-old board would replay hundreds of thousands of updates on open. Mitigation: snapshot compaction from Phase 7 — load the newest snapshot and only replay what came after.

  • Arabic text on a canvas

    The browser shapes Arabic correctly in the editing overlay, but the canvas draws its own text and needs the same font metrics or the caret drifts. Handled in Phase 3 rather than retrofitted — flag it fast if item 6 of that checklist looks off.

  • Firebase is a second vendor for one feature

    It buys you a lot (token refresh, session handling, popup flows), but it's another dashboard and another outage surface. If you'd rather be pure Cloudflare, Google sign-in can be done directly in the Worker — a day's work, and a day of security-sensitive code you'd own. Say the word before Phase 5.

  • The undo-over-someone-else's-edit policy

    Genuinely ambiguous, and it produces bug reports nobody can reproduce if it isn't decided. Decide it at Phase 4; I'll write tests either way.

  • Cloudflare's build system is plainer than Vercel's

    One build at a time, 500 a month. Not a problem at this pace, but pushing twice quickly means the second build queues.

  • Undo across sessions (P15)

    Today's undo lives in the open tab. Keeping it after the board closes means storing each person's recent steps and being able to replay them against a board others have changed since. It is the least certain phase left, so it starts with a small trial.

  • Scope

    Twenty-one phases, counting 14.1 and 14.2, is a lot. The order is chosen so that each one leaves you a whiteboard worth using — keyboard use and hardening come last so they cover what you will actually use.

Every phase, 0–18, is built and deployed. What's left is your domain (Phase 18, item 6), your week of free-tier figures (item 5), and checking the built phases against their lists. Anything parked is there whenever you want it.
